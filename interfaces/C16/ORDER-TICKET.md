# C16 Production Order-Ticket Interface

Status: FROZEN
Date: 2026-08-18

## Purpose

This document resolves the serialization incompatibility discovered during
C16 system acceptance.

The business order rows produced by `psx-ml-research` remain based on the
accepted `build_session_open_orders(...)` output.

The cross-repository transport artifact consumed by `stock-watcher` is JSON.

## Canonical watcher-facing artifact

The ML production pipeline MUST emit:

    order_ticket_<execution-date>.json

The document MUST be a top-level non-empty JSON array of row objects.

Valid:

    [
      { ...order row... },
      { ...order row... }
    ]

Invalid:

    {
      "orders": [
        ...
      ]
    }

## Business schema

The JSON rows must represent the same business rows generated by the accepted
ML `build_session_open_orders(...)` function.

No policy transformation or manual editing is permitted between ML generation
and watcher import.

At minimum the rows must contain all fields required by the existing watcher
ticket validator.

Allocation identity remains:

    A07_P4_25_P5_75

`signal_date` and `execution_date` must be serialized as ISO dates:

    YYYY-MM-DD

## Parquet artifact

ML MAY continue emitting the existing Parquet order ticket for research,
inspection, deterministic comparison, and provenance.

The Parquet artifact is not the C16 cross-repository handoff artifact.

The JSON artifact is the canonical C16 watcher-facing ticket.

## Watcher

`stock-watcher` MUST retain its existing JSON importer.

No watcher runtime modification is required solely to support Parquet.

## Provenance

The ML production manifest must include identity/hash information for the
watcher-facing JSON artifact in addition to any retained Parquet artifact.

## Acceptance

SYS-AT07 requires that the JSON ticket emitted directly by the ML production
pipeline be passed unchanged to:

    stock-watcher/a07_orders.py

and import successfully.

No conversion command, manual edit, field rename, or envelope transformation
is allowed during system acceptance.
